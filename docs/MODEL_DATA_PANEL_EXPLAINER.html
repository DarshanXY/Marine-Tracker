Marine Plastic Tracker
Model, Data, and Training Explained

This document explains, in simple words, which model we use, what data we trained it on, how we cleaned and prepared that data, how the model works inside the project, and what results we got.

Prepared from the current codebase on: Thursday, July 30, 2026

Main files used for these facts: python_engine/models/metrics.json, python_engine/ml/datasets/*.py, python_engine/ml/train_perpixel_gpu.py, python_engine/ml/inference_engine.py, and python_engine/main_pipeline.py.

1. Project idea in one line

Our project takes free Sentinel-2 satellite images of the sea, finds pixels that may contain floating material, uses AI to decide whether that material is plastic or not, groups nearby plastic pixels into hotspots, and then predicts where those hotspots may drift over the next 72 hours.

Simple way to say it to the panel: "We built a system that looks at satellite images, finds possible floating waste, checks whether it is plastic, and shows where it may move next."

2. Which model do we use?

Main deployed model
marinenet.onnx
This is the model currently used in the live pipeline.
Model type
Per-pixel MLP
A neural network that classifies one candidate pixel at a time.
Output classes
4 classes
Plastic, Algae, Sea_Foam, and Water.

The main model is a 3-seed ensemble of per-pixel MLPs. In simple words, that means we trained the same type of neural network multiple times and averaged their outputs so the final result is more stable and more reliable.

The current shipped model uses 11 input features made from 5 Sentinel-2 bands plus derived indices:

  • Raw bands: B04, B06, B08, B8A, B11
  • Derived features: FDI, NDVI, PI, MNDWI, NDVI_RE, BRIGHT
What this model does: it looks at the spectral values of a candidate pixel and decides whether that pixel is more likely to be Plastic, Algae, Sea Foam, or Water.

5. How did data preprocessing work?

We did not put raw dataset files directly into the model. We first cleaned and converted them into the exact format our project needs.

Step 1
Download raw datasets
We stored the original dataset files inside the data/ folder.
Step 2
Read official split files
We used each dataset's train, validation, and test lists instead of making random splits by hand.
Step 3
Pick matching bands
We selected the Sentinel-2 bands that the live pipeline also uses.
Step 4
Compute extra features
We calculated FDI, NDVI, PI, MNDWI, NDVI_RE, and BRIGHT from the raw bands.
Step 5
Map labels
We converted the original 15 dataset classes into our 4 project classes.
Step 6
Remove unusable rows
We dropped invalid, excluded, or non-finite pixels.
Step 7
Cache as .npz
We saved clean arrays like marida_train.npz and mados_train.npz.
Step 8
Train the model
Only after preprocessing did we train and export the final ONNX model.

Important preprocessing details

  • MARIDA: we read 11-band Sentinel-2 GeoTIFFs and their class masks, then converted MARIDA's 15 classes into our 4 classes.
  • MADOS: we did the same, but we also manually handled band resolution differences by upsampling 20 m and 60 m bands to the 10 m grid.
  • PLP: we matched target dates to satellite scenes, reprojected target points into the image coordinate system, read center pixels, and built validation samples.
  • RFO: we read labeled point locations, cropped 64 x 64 image chips, and also extracted center-pixel features for comparison tests.

6. How did we manage to put the dataset into our project?

Raw data storage

We kept downloaded benchmark datasets inside the project's data/ folder. This made the datasets part of the project workflow, but separate from source code.

Clean training caches

After preprocessing, we saved compact cache files like python_engine/models/marida_train.npz and mados_train.npz so future training runs could start faster.

In simple words, we used a two-stage setup:

  • Stage 1: keep the original dataset files in data/
  • Stage 2: convert them into cleaned model-ready arrays in python_engine/models/
Simple panel answer: "We downloaded the datasets into our project's data folder, wrote our own Python loaders to read them, cleaned and converted them into numpy cache files, and then used those cache files for training."

7. Which model did we train, and what does it do?

Model Status What it does
marinenet.onnx Main deployed model Classifies each candidate pixel as Plastic, Algae, Sea_Foam, or Water.
clay_head.pt Second-stage verifier Looks at the whole hotspot chip and gives a second opinion using Clay embeddings.
marinenet_patch.onnx Experimental only A patch CNN we trained and evaluated, but did not keep as the default because it performed worse.

The most important trained model is marinenet.onnx. It is the one actually used in the project's live scanning pipeline.

8. Full training process of the main model

Stage 1
Load MARIDA and MADOS
Our custom loaders read the official train, val, and test splits.
Stage 2
Build feature vectors
Each labeled pixel was converted into 7 features first, then 11 for the improved GPU model.
Stage 3
Combine both datasets
We merged the clean MARIDA and MADOS arrays into one training set.
Stage 4
Train on GPU
We trained a deeper per-pixel MLP using the RTX 4050 laptop GPU.
Stage 5
Evaluate on held-out test data
We checked performance only on test pixels the model never saw during training.
Stage 6
Export to ONNX
We exported the final trained model into marinenet.onnx.
Stage 7
Check ONNX parity
We verified that ONNX predictions match the training model output.
Stage 8
Use it live
The Python engine loads the ONNX model at runtime for real scans.
Key implementation point: we trained the model in PyTorch, but we deployed it in ONNX Runtime so the live engine stays lighter and easier to run.

9. How does the live system use the trained model?

Training time and runtime are different.

During training

  • Read external datasets from data/
  • Convert pixels into model features
  • Train the MLP
  • Export marinenet.onnx

During live detection

  • Download a new Sentinel-2 scene
  • Mask clouds and land using SCL
  • Compute FDI to find candidate pixels
  • Build the same 11 features
  • Run marinenet.onnx to classify each candidate
  • Cluster high-confidence plastic into hotspots
  • Ask Clay for a second opinion
  • Run drift forecasting

So the model does not directly read raw dataset folders during live use. The dataset folders are for training and validation. In live use, the model reads new satellite pixels and applies the same feature logic it learned during training.

12. What did we implement manually by ourselves?

  • We manually wrote dataset loaders for MARIDA, MADOS, PLP, and RFO.
  • We manually mapped raw dataset labels into our 4 project classes.
  • We manually computed the same spectral features used by the live pipeline.
  • We manually handled MADOS band upsampling to a common 10 m grid.
  • We manually created clean cached training files in .npz format.
  • We manually wrote the training scripts for the combined model and the GPU-improved model.
  • We manually exported the trained model to ONNX and loaded it into the Python engine.
  • We manually connected the model to the live pipeline: satellite download, FDI, classification, clustering, Clay verification, and drift.
Simple panel answer: "We did not just download a ready-made model. We wrote our own data loaders, preprocessing, feature engineering, training scripts, ONNX export, and runtime integration."

13. One-minute script for the panel

"Our project uses a main AI model called marinenet.onnx. It is a per-pixel neural network that looks at Sentinel-2 spectral values and classifies each candidate as Plastic, Algae, Sea Foam, or Water.

We trained the final deployed model on two real labeled datasets: MARIDA and MADOS. Together they gave us 1,081,615 labeled training pixels. We stored the raw datasets in the project's data folder, wrote our own Python loaders, cleaned the data, mapped the original labels into our 4 project classes, computed the spectral features, and saved clean cache files for training.

After that, we trained the model on GPU, evaluated it on held-out test data it had never seen, and exported the final model to ONNX for live use in the project. The current main model got 98.99% accuracy and 0.8175 Macro-F1 on the combined held-out test. We also use a second model, Clay, as a verifier to give hotspots a second opinion and improve confidence.

So the full process is: download satellite image, compute FDI, run the trained model, group plastic pixels into hotspots, verify them with Clay, and then forecast drift."
